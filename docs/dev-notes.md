# 開發手冊

待辦與待驗證事項。每一條記錄「現況是什麼」「為什麼要動」「怎麼算做完」，
避免下次回來又要重新翻程式碼。

數字一律以 value units（台）為單位；1 底 = `BASE_UNITS` = 3 台

## 1. 讓機器能選擇開大明槓

### 現況

槓不是一個「決策」，是一個開關。

- `play_game(..., kong_policy="none")` 是預設值（`taimahjong/selfplay.py:658`），
  所以**一般對局裡四家從頭到尾都不槓**，連暗槓、加槓都不會出現。
- 三種政策 `none` / `concealed_added` / `all` 是固定設定，逐座位指派
  （`_seat_kong_policy`，`selfplay.py:643`），不是依當下局面算 EV 決定的。
- 自摸槓走 `_self_draw_kong_choice`（`selfplay.py:237`），只做「不增加向聽」的
  安全性檢查；大明槓走 `_big_kong_caller`（`selfplay.py:276`），條件是下游有
  某家的政策剛好是 `all`。

結果是：**引擎沒有「這一手該不該槓」這個決策點**，訓練器與測驗也就出不了這種題目，
EV 排名裡也沒有槓的候選項。

### 為什麼要動

槓是台灣麻將少數幾個「一步就能改變整手牌價值與風險」的動作，而且新手最容易做錯。
它應該跟切牌一樣，是被算出來的選擇，不是被設定決定的。

### 做完的定義

- [ ] 槓成為 `ev_rank` 的候選動作之一，跟切牌用同一套終局 rollout 比較，
      而不是靠 policy 開關。
- [ ] 三種槓（暗槓／加槓／大明槓）各自估值，因為它們的成本結構不同（見第 2 條）。
- [ ] 訓練器能出「要不要槓」的題目，並在回饋裡顯示 EV 差。
- [ ] `kong_policy` 保留為實驗用的強制開關（`scripts/kong_ev.py` 需要它做對照），
      但不再是正式對局的唯一決定方式。

### 注意

改這個會動到 `selfplay.py` 的對局主迴圈與 `data/calibration.json` 的產生條件
（校準表來自自對局，四家的槓行為改變會改變牌局分布）。**校準表需要重跑，
`docs/` 裡引用舊表的數字要一併確認。**

## 2. 大明槓的代價要真的量出來

### 現況

「大明槓比較差」目前是**寫死在規則實作裡的假設**，不是量出來的結論。

程式碼裡的不對稱：

| | 補牌 | 可否槓上開花 |
|---|---|---|
| 暗槓 / 加槓 | 有 | 可以（`selfplay.py:757` 設 `kong_bloom=True`） |
| 大明槓 | 有 | **不行**（`selfplay.py:298`："Open, no bloom eligibility"） |

`selfplay.py:844` 的註解寫明理由：第四張來自別人的棄牌，所以不算槓上開花。
這是家規建模選擇 —— 別的牌桌未必這樣算。

實測（paired，seed base 40001，見 [experiments.md](experiments.md)）：

| n | mean | 95% CI | 結論 |
|---:|---:|---|---|
| 1000 | −0.112 | [−0.254, +0.030] | 跨 0 |
| 3000 | −0.031 | [−0.108, +0.045] | 跨 0，且低於 0.10 效果門檻 |

**樣本加三倍，點估計往 0 靠了 3.5 倍。** 所以 −0.112 是雜訊，不是效果。

### 這個量法本身就有問題

上面量的是「**所有可以大明槓的局面**」的平均值，而那是一鍋混合物：

- 有些局面補牌能改聽、增加有效張 → 槓有實質價值
- 有些局面補牌完全不改變聽牌 → 槓只是白丟門清

兩者相加平均，效果互相抵銷成接近 0。**所以測不出效果，不代表沒有效果，
只代表這個問法問得不好。** 下次要控制條件再測，不要再量總平均。

### 待驗證的問題

**a.（優先）在「完全同聽」的控制條件下量。**
只取滿足以下條件的局面：

1. 槓之前已經聽牌
2. 槓完之後聽牌種類與剩餘有效張數**完全不變**
3. 大明槓本身不加台
4. 原本門清（所以槓完少 1 台）

在這個子集裡，攻擊面的收益幾乎不變而和牌價值確定少 1 台，
所以理論預測是 **EV(大明槓) < EV(Pass)**，而且方向應該穩定、不該跨 0。
這是一個可以被證偽的預測，比量總平均有力得多。

**但要注意本專案的實作細節，理論預測不能照抄：**

- 補牌**可以直接自摸胡**（`selfplay.py:862` 走 `_settlement("tsumo", ...)`），
  只是不帶 `kong_bloom=True`，少那 1 台槓上開花。所以不是「補牌不能胡」。
- 大明槓後 `current = big_caller`，**中間座位的摸牌回合被跳過**。

也就是說在這個實作裡，大明槓買到的是「立刻多摸一張（有機會直接胡）」
加上「吃掉對手回合」，付出的是門清 1 台。它**不是**被 Pass 嚴格支配。
所以驗收標準不是「必須為負」，而是：

> 在完全同聽的控制條件下，EV(大明槓) − EV(Pass) 應該落在
> 「−1 台（純粹損失門清）」與「補牌立即胡的機率 × 和牌值 ＋ 跳回合的價值」
> 兩者相抵之後的一個小負數。**如果跑出明顯正值，先懷疑實作，不要當成策略結論。**

**b. 槓上開花的禁令到底值多少？**
`experiments.md` 記載這兩批對局裡**槓上開花一次都沒發生**。如果它幾乎不觸發，
那「大明槓不能槓上開花」在數據上的成本就趨近 0 —— README 把它列為主要理由是講不通的。
做法：把大明槓改成 bloom-eligible 跑一組對照。預期差異測不出來；
**如果真的測不出來，就要修 README 的措辭**。

**c. 成本到底來自哪裡？**
把總效果拆開：
- 破門清（少 1 台，只在門清胡牌時才實現）
- 四張牌鎖死造成的彈性損失
- 對手獲得的資訊（明擺的槓等於公開一組牌）

對照好處：
- 立刻多摸一張（且該張可以直接胡）
- 跳過中間座位的回合（對手少摸，等於降低他們的進張與胡牌機會）

目前的猜測是**這兩項好處大致抵銷了破門清**，所以總平均接近 0；要有數據才能這樣寫。

**d. 要多大的樣本才夠？**
n=3000 時 se = 0.039。若真實效果是 −0.03，要讓區間排除 0 需要 n ≈ 27,000。
先想清楚這個效果值不值得花這麼多算力 —— 也可能答案就是
「它小到不必當成一條打牌準則」，那本身就是結論。
控制條件（問題 a）會讓效果變大、變異變小，應該優先做那個而不是硬加樣本。

**e. 對局角色會不會改變結論？**
現有實驗是「座位 0 開槓、其餘三家不槓、四家都是 `attack`」。
換成 `cautious` / `ev_aware` 對手、或多家同時可槓，結論可能不同。

### 做完的定義

- [ ] 上面 a～e 每題都有一個可重跑的指令與一份帶 CI 的結果。
- [ ] `experiments.md` 的措辭與實測一致，不留任何沒有 CI 支撐的方向性宣稱。
- [ ] README 對大明槓的敘述改成規則層面的論證，或補上真正的數據。

### 現在可以講與不能講的話

- ✅「家規讓大明槓在台數上較差（0 台、破門清、不能槓上開花）。」
- ✅「實測到 3000 局仍分不出顯著差異；補牌與跳回合的價值大致抵銷了代價。」
- ⚠️ 不要說「被 Pass 嚴格支配」— 本實作的補牌可以直接胡，且會跳過對手回合。
- ❌「數據證明大明槓是負期望值。」— 區間跨 0，講不得。
- ❌ 引用 −0.112 當招牌數字。

`test_daiminkan_is_not_positive_ev_under_house_rule` 斷言的是
`with_daiminkan <= added_only + 0.05`，那是「不得更好」的防呆，
不是「一定更差」的證據。

## 3. 切牌政策看不到自己坐在哪個順位

### 現況

`_production_discard_policy` 是**座位無關、牌牆深度無關**的純進張規則：同一手牌
不管是行動家自己、他的下家、還是牌牆最後一個摸得到的人，切出來都一樣。

2026-08-24 的經驗賽局量測（`taimahjong/empirical_game.py`，方法與完整結果見
[equilibrium-plan.md](equilibrium-plan.md) 步驟 3）顯示這是個真的漏洞。在 ≤4 張牌牆、
無鳴牌的殘局子賽局，{efficiency, safety} 兩策略抽象下，把某一家改吃 safety 的收益按
**相對摸牌順位**拆開（0 = 行動家，26 局面 × 400 世界，bootstrap 重抽局面）：

| 相對順位 | 收益 | 95% CI | 判定 |
|---:|---:|---|---|
| 0（行動家） | +0.2590 | [−0.008, +0.561] | 未判定（差一點） |
| 1（下家） | −0.1518 | [−0.305, −0.000] | **防守反而虧** |
| 2 | +0.0066 | [−0.081, +0.094] | 未判定 |
| 3（最後摸） | +0.1251 | [+0.041, +0.212] | **防守有賺** |

順位 1 在牌牆 4 張那格（18 個局面）是 −0.2426，[−0.430, −0.055]。

所以**不是「多防守就對」**：最後一個摸牌的人防守有賺，下家在還有 4 張可摸時防守要虧
0.24 台。正確行為取決於順位，而政策看不到順位。

同一份量測也證明了全 efficiency 的組合**不是**均衡（單邊偏離最多多賺 0.265 台，
95% CI [+0.082, +0.519]），但**沒有**解出均衡——16 個 profile 排除 11 個，剩 5 個
在這個預算下分不開。

### 為什麼要動

這是目前少數「量出方向、且指得出該改哪個函式」的缺口。多數 EV 討論停在「這個數字對
不對」，這一條停在「政策少看了一個特徵」，可以直接寫成程式。

### 待驗證的問題

**a.（優先）以角色重建經驗賽局。**
現在賽局的「玩家」是絕對座位編號，但語料裡行動家 13 局在座位 0、13 局在座位 1，
同一個編號在不同局面扮演不同角色。改成「行動家／順位 1／順位 2／順位 3」語意才乾淨，
而且每個局面對每個角色都貢獻一個觀測（現在座位 2、3 各只在一種角色出現）。
改動小、直接複用現有 payoff 表，且順位正是政策該看卻沒看的特徵。

**b. 加局面，不要加世界。**
叢集 bootstrap 重抽的是局面，所以世界再加只會把每個局面的均值磨得更準，26 個叢集的
離散度不變。CI 半寬約 ∝ 1/√(局面數)，要把 ±0.22 壓到 ±0.10 需要約 5 倍局面數。
牌牆深度的拆解（現在每格只有 2–4 個局面）也只有這條路能救。

**c. `safety` 換成真的放銃機率估計。**
現在的「未見剩餘為 0」是很粗的現物近似。抽象裡的策略越接近真正的候選打法，
均衡才越有參考價值。這是換一個賽局，不是改進這個賽局，所以排在 a、b 之後。

**d. 政策本身怎麼改。**
在 a 之後才有意義：知道每個順位該偏攻或偏守，才談得上把順位（很可能還有牌牆深度）
接進 `_production_discard_policy`。不要在只有現在這 26 個局面的解析度下就硬調參數。

### 做完的定義

- [ ] a～c 各有一個可重跑的指令與一份帶 CI 的結果。
- [ ] 順位對切牌的影響有一個方向穩定、CI 不跨 0 的結論（至少涵蓋順位 1 與 3）。
- [ ] `_production_discard_policy` 看得到相對順位，且改動前後有 paired 對照。

### 現在可以講與不能講的話

- ✅「在這個殘局子賽局的兩策略抽象下，production 的組合不是均衡。」（否定句，有 CI）
- ✅「防守的價值取決於相對摸牌順位，而現行切牌政策看不到順位。」
- ⚠️ 不要把 +0.259（行動家自己該不該防守）當結論——叢集層級差一點就跨零。
- ❌ 不要說「解出了殘局的均衡」。沒有。5 個 profile 分不開。
- ❌ `gto`／`理論最佳`／`最佳解` 維持封鎖，`tests/test_claims.py` 一條都沒解除。

判準寫死在測試裡：CI 完全在 0 以下才算「證明是均衡」，跨 0 就是「沒分開」。
`test_the_production_profile_is_shown_not_to_be_an_equilibrium` 釘住否定句，
`test_no_profile_in_this_abstraction_is_shown_to_be_an_equilibrium` 釘住
「沒解出來」這句話不會在無人注意時過期。兩個都是 slow，只在夜間排程與手動觸發跑。
