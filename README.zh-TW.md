# 台灣麻將向聽與進張（M2）

這個套件會幫台灣十六張麻將算「向聽數」。向聽數就是：你現在離「聽牌」還差幾張
有效牌。差 0 張就是已經聽牌了。

它只算 34 種普通牌（萬、筒、條、字），不管花牌，也不算特殊牌型。

牌用一種簡寫法：數字寫在花色前面。`m` 是萬、`p` 是筒、`s` 是條、`z` 是字牌
（1 到 7）。例如 `123m456p789s1122334z` 就是 16 張牌。

胡牌要湊成五組面子（順子或刻子）加一對將，也就是 17 張。這裡的向聽數是這樣定的：
湊滿 17 張（已經胡）記成 `-1`，16 張聽牌記成 `0`。如果你已經吃碰槓、副露亮在外面，
用 `--melds` 告訴程式，每一組會讓要湊的暗牌少 3 張。

算一手牌：

```bash
python3 -m taimahjong "123m456p789s1122334z"
```

如果手上是「16 張」的暗牌，加 `--ukeire` 會列出每一張能讓你更接近胡牌的進張，
還有這些牌總共還剩幾張沒出現：

```bash
python3 -m taimahjong "123m123p123s1112223z" --ukeire
```

如果手上是「17 張」的暗牌（摸完還沒切），加 `--analyze` 會幫你把每一種切牌排名。
排法是：先看切完後向聽數誰比較小，一樣的話再比誰的進張多：

```bash
python3 -m taimahjong "123m123p123s11122233z" --analyze
```

程式也有 Python 介面：`ukeire(counts, melds_declared=0, visible=None)` 和
`discard_analysis(counts, melds_declared=0, visible=None)`。`visible` 是一個 34
格的陣列，記你在別的地方看到的牌，CLI 用 `--visible "..."` 也能傳。某一種牌還剩
幾張的算法很簡單：`4 −（你手上有幾張）−（別處看到幾張）`。就算某種牌一張都不剩，
只要它理論上能幫你進步，還是會列出來，這樣「已經沒牌可等」的窘境你也看得到。要
注意：同一種牌，「手上 + 看到的」加起來不能超過 4 張。

## M3 模擬

`win_probability(counts, turns, melds_declared=0, visible=None, sims=5000,
seed=None)` 會用「發很多次牌來估機率」的方法（也就是蒙地卡羅模擬），對著 136 張
普通牌試很多局。牌池裡每種牌 4 張，扣掉你的手牌和你看過的牌；花牌不算。每一局都
是抽了就不放回，切出去的牌也不會又跑回牌池。抽到不能胡的牌時，程式就照 M2 的最佳
切牌（切完向聽最小、進張最多）繼續打。

跑完會告訴你：每摸一巡之後，累積的聽牌率和胡牌率各是多少。如果你一起手就聽牌，這
會算進「第一巡的聽牌率」裡，不另外開一欄。這只是**自己摸牌**的估計，不管對手怎麼
切、不管放槍、不管台數、也不管對手會怎麼打。

跑一次可以重現的模擬（給了種子就會每次一樣）：

```bash
python3 -m taimahjong "123m123p123s1112223z" --simulate --turns 10 --sims 5000 --seed 42
```

它會一巡一巡印出累積聽牌率和自摸胡牌率，最後印總計，再提醒你這只算自摸。

跑測試（pytest 只在測試時要用）：

```bash
python3 -m pytest tests/ -q
```

## M4a 放槍危險度（單一對手）

`taimahjong.danger` 是一個「照固定規則算」的工具，用來估切某張牌給某個對手放槍
有多危險。它**還沒校準過**，也就是說它給的數字**不是**真正的機率，只是相對的
危險高低；真正校準要等後面的里程碑。它的做法是：把「靠這張牌就能胡」的各種聽牌型
都列出來，看看對手要湊那些型所需要的牌是不是還在牌牆裡，然後把做得到的那些型的
分數加起來。

| 牌型或規則 | 常數 | 預設 |
| --- | --- | --- |
| 兩面順 | `RYANMEN_WEIGHT` | 4.0 |
| 崁張順 | `KANCHAN_WEIGHT` | 2.0 |
| 邊張順 | `PENCHAN_WEIGHT` | 2.0 |
| 對碰 | `SHANPON_WEIGHT` | 2.0 |
| 單騎 | `TANKI_WEIGHT` | 1.0 |
| 要判斷缺門所需的最少數字牌河 | `MIN_RIVER_NUMERIC` | 6 |
| 某花色數字牌河占比偏低的門檻 | `LOW_SHARE` | 0.15 |
| 稀少花色乘數 | `SUIT_SCARCE` | 1.5 |
| 缺門花色乘數 | `SUIT_VOID` | 2.0 |
| 副露全在同一花色的乘數 | `MELD_FLUSH` | 2.0 |
| 上述情況下的字牌 | `MELD_FLUSH_HONOR` | 1.5 |
| 牌河出現所需牌時的折扣 | `SHAPE_RIVER_DISCOUNT` | 0.3 |

判斷能不能胡，要看對手手上放不放得下那些牌：單騎要 1 張、對碰要 2 張、順子要它
兩邊的鄰牌各 1 張。判斷對手缺不缺某門，用他切出的數字牌來看：等他切了至少六張
數字牌以後，某花色占比低於 15% 就當「稀少」、完全沒切過就當「缺門」，危險往上加。
「同花判讀」在這種情況觸發：對手所有副露都在同一數字花色，而且他牌河最新的三分
之一裡都沒有那門牌——這時就把那門和字牌的危險調高。如果「同花」和「稀少／缺門」
剛好指向同一門，就取兩者裡比較大的那個，不會兩個相關的訊號重複相乘。

牌河證據是分牌型算的：某個牌型需要的牌，只要在對手牌河裡出現過，那個型就打 0.3
折。如果那張相符的牌落在最新三分之一，折 0.3；只有更早出現的才折得比較少
（`sqrt(0.3)`）。但這永遠不代表絕對安全。台灣麻將沒有日本立直那種「永久振聽」，
只有暫時的過水，所以不能照搬「現物」或「筋牌」當成 100% 安全，牌河出現的牌只會
幫對應的牌型打折而已。

用 CLI 時，給它一副「切牌前、17 張」的暗牌：

```bash
python3 -m taimahjong "123m123p123s11122233z" --danger --opp-river "456m789p" \
  --tile "3z"
```

它會照 M2 的切牌順序印出來，另外多一欄 `Danger`；它**不會**把效率和危險混成一個
分數。`--tile` 會印那張牌各種聽牌型的細節。`--opp-river` 用簡寫法、由舊到新排。
對手的副露用分號隔開傳，例如 `--opp-melds "123s;777s"`。在 danger 模式下，
`--visible` 指其他公開牌；對手牌河和副露程式會自動幫你加進去。

用 Python 介面時，`danger_score(tile, opponent, visible, own_hand)` 要求你自己先把
對手牌河和副露（還有其他所有看得到的公開牌）都放進 `visible`。`own_hand` 要放
**切牌後**的暗牌，所以不含你正要切的那一張。程式把每種牌還剩幾張算成
`4 − visible − own_hand − 已切的那張`，並檢查不會超過 4 張，所以絕不會重複算到
你切的牌。`rank_discards(counts17, opponent, visible, melds_declared=0)` 則是包住
M2 的排序，再幫每一項加上一份危險評估。

## M4a+ 對手狀態（聽牌、蓋牌、宣告 migi）

`taimahjong.danger` 裡對「對手現在什麼狀態」的判斷，一樣是照固定規則、而且
**還沒校準**。它們是幫你讀牌的方向感，不是量出來的真機率；校準要等後面。
`RiverEntry(tile, origin)` 記一張牌河牌，`origin` 是 `"tsumogiri"`（摸切）、
`"tedashi"`（手切）或 `"unknown"`（不知道）。你也可以只放一個整數，那就當來源不明。

`parse_river()` 和 `format_river()` 都在 `taimahjong.danger` 裡。牌河的寫法可以在
數字後面、花色前面加符號：`*` 是摸切、`.` 是手切。例如 `1*2.3m` 就是 1m 摸切、
2m 手切、3m 不知道。程式在數「最近連續摸切了幾張」時，遇到「不知道」的會當中性：
從新往舊數，它既不加分也不中斷；碰到第一張確定的手切才停。

`tenpai_score(opponent, turn)` 會回傳
`TenpaiAssessment(score, signals, recent_wait_change)`，估對手大概多接近聽牌。用到
的常數有 `TENPAI_BASE_BY_MELDS`（最強的訊號，因為鳴牌越多、暗牌越少）、
`TENPAI_TURN_INCREMENT`、`TENPAI_TURN_CAP`、`TSUMOGIRI_RUN_INCREMENT`。到了第 9 巡
（`LATE_TURN`）之後，如果最近 2 張（`RECENT_TEDASHI_WINDOW`）裡有手切，就設
`recent_wait_change`，並用 `RECENT_TEDASHI_MULTIPLIER` 把先前的牌河判讀調弱一點
（因為對手可能剛換聽）。`rank_discards` 會保留原始的 `danger` 和 `tenpai`，再加上
`tenpai_score`，並附一個方便看的 `expected_danger = danger.score × tenpai_score`。

`fold_score(opponent, others_discards)` 看對手最近 4 張（`FOLD_WINDOW`）切牌，判斷
他是不是在蓋牌（不打了、只求安全）。至少要有 3 張（`MIN_FOLD_SAMPLE`）才算。它對
每張牌取「最安全的解釋」再平均：別家也切過同一張記 1.0、字牌記 0.6
（`HONOR_FOLD_WEIGHT`）、么九牌記 0.3（`TERMINAL_FOLD_WEIGHT`）。手切的中張
（3 到 7）記 0。一個在蓋牌的對手，胡牌威脅就低了、流局機率就高了；M7 會用這個
分數把那個對手的危險直接歸零。

這套規則裡唯一的宣告方式是家規 **migi**。它只能在你第一或第二次切牌時宣告（全桌
前八張切牌內），而且要在任何吃碰槓之前。`OpponentView` 用 `declared_at` 記宣告是
在第幾張牌河，只能是 0 或 1。`DECLARED_TAI = 8` 先留著給以後的計分用。宣告過的
對手一定聽牌（`1.0`）、不可能蓋牌（`0.0`）、而且手牌鎖死：他宣告之後才切出來的
任何一種牌，都不可能是他要胡的，程式回報 `declared_safe`、危險就是 0。這是硬規則，
和宣告前的牌河證據不一樣（那只是打折），因為台灣規則沒有日本那種永久振聽。

在 `--danger` 模式下，用 `--opp-declared 0` 或 `--opp-declared 1` 表示 migi，
`--others "..."` 當作判斷蓋牌的安全參考。輸出會多出對手聽牌和蓋牌的欄位、還有一欄
`ExpDanger`；被硬排除的牌會印 `SAFE(declared)`。

## M4b 自對局校準

`taimahjong.selfplay` 讓四個「照固定策略打」的機器人，在同一副 136 張普通牌裡對局。
每家發 16 張、莊家先摸，用 M1 判斷自摸和榮和，一直打到有人胡或活牌牆抽完
（留 16 張當牌山尾）為止。每次切牌都會記一筆資料：當時看得到的對手狀態、真正的
聽牌情況、有沒有放槍、還有拿來校準用的 M4a 危險分數。

這個模擬器故意不做花牌和補花、不做槓、也不做台灣的過水規則。它是拿來試策略的，
不是完整的規則實作。榮和照下家優先；碰和下家吃只有在「碰或吃完之後的最佳切牌會
讓向聽真的變好」時才允許。家規 migi 可以在前兩次切牌、任何鳴牌之前用；宣告過的
玩家除非胡牌，不然只能把摸到的牌切掉。他鎖定的那些切牌上不做鳴牌，好讓宣告後的
牌河看得清楚。

四家預設是兩個 `attack`、兩個 `cautious` 機器人。Attack 就打 M2 的最佳切牌。
Cautious 大致一樣，只有在向聽 2 以上、又碰到已宣告或已四副露的對手時，才改切
M4a 危險最低的那張。這是故意的，好製造出看得到的「蓋牌時機」。

M8 這一版改了「放槍怎麼算」的參考基準，因為發現舊版在最危險那一段會失準。舊版
（已提交的 3,751 局表）在「沒放槍」時用三家對手中的最高分，卻在「放槍」時只用實際
胡家的分。結果它各分數段的放槍率是 0.0000、0.0013、0.0043、0.0166、0.0322、
0.0306、0.0228——最高的那幾段居然反過來變小了。於是重跑一次 400 局的診斷
（種子 9001–9004），花色和同花的設定維持不變（`SUIT_VOID=2.0`、`SUIT_SCARCE=1.5`、
`MELD_FLUSH=2.0`），把兩種算法擺在一起比：

| 分數段 | 三家取最高 | 逐對手 |
| --- | ---: | ---: |
| [0,1) | 0/549（0.0000） | 0/3,832（0.0000） |
| [1,2) | 2/941（0.0021） | 2/2,126（0.0009） |
| [2,4) | 16/2,657（0.0060） | 16/9,793（0.0016） |
| [4,6) | 28/1,938（0.0144） | 28/4,967（0.0056） |
| [6,9) | 73/2,708（0.0270） | 73/9,616（0.0076） |
| [9,13) | 104/3,136（0.0332） | 104/8,972（0.0116） |
| [13,+) | 69/3,167（0.0218） | 69/5,982（0.0115） |

「逐對手」這種算法：每次切牌，對每個還在場的對手各記一列；榮和只算在真正胡家那
一列。這樣一改，不用動任何設定，分數就恢復「越高、放槍越多」的順序了。為什麼在意
這條原始曲線？因為危險分數要能拿來排名，前提就是「分數高＝放槍多」；這件事要先
成立，後面再用統計方法把雜訊抹平才有意義。

已提交的重建版是 2,000 局（種子 10001–10008）：

| 危險分數段 | 放槍數 / 觀察數 | 放槍率 |
| --- | ---: | ---: |
| [0,1) | 1 / 19,061 | 0.0001 |
| [1,2) | 3 / 10,321 | 0.0003 |
| [2,4) | 90 / 48,783 | 0.0018 |
| [4,6) | 142 / 24,533 | 0.0058 |
| [6,9) | 398 / 47,615 | 0.0084 |
| [9,13) | 514 / 43,952 | 0.0117 |
| [13,+) | 347 / 30,117 | 0.0115 |

最後 9–13 到 13+ 那一格有稍微往下掉，但差距比「合併估計的 1.5 個標準誤」還小，
算在容許範圍內，所以通過「大致遞增」的檢查。JSON 裡記了種子、逐對手的算法、還有
各種設定值。要加新資料前，請從頭重建；千萬別把 M8 之前「取最高」的舊表混進來：

```bash
rm data/calibration.json
python3 -m taimahjong --selfplay --games 250 --seed 10001 --out data/calibration.json
python3 -m taimahjong --selfplay --games 250 --seed 10002 --out data/calibration.json
python3 -m taimahjong --selfplay-report data/calibration.json
```

這個 JSON 存了可以合併的 `counts`，還有幾張算好的表：對手聽牌的經驗機率
（依副露數、第幾巡、最近摸切幾張分格）、原始的放槍比率、把它整理成「越危險放槍
越高」的校準表，還有兩種機器人蓋牌視窗的平均。查表時，觀察數少於 30 的格子當作
沒資料；查危險時，會在有資料的分數段中點之間做內插。只要 `data/calibration.json`
在，`--danger` 就會同時顯示未校準的分數和校準後的聽牌率、放槍率。

這些機率是**對這些機器人**校準出來的，配它們的貪婪鳴牌規則和這些簡化設定——不是
對真人的台灣麻將牌局。

## M5a 台數計分

`taimahjong/scoring.py` 幫一副胡牌算台，還會一項一項列給你看。家規寫在模組常數裡：
一底等於 `BASE_UNITS`（3）台；標準台灣台數表（莊 1、連 N 拉 N 是 2N、門清／自摸／
獨聽 1、平胡／全求人／三暗刻 2、碰碰胡／混一色／小三元 4、四暗刻 5、清一色／
大三元／小四喜／五暗刻 8、字一色／大四喜 16、圈風／門風／三元牌刻 1）；宣告 migi
加 `DECLARED_TAI`（8）；天胡／地胡的家規值是 16／8 台。花牌不算——`WinContext.extra`
是留給花牌用的欄位。

**槓的家規（2026-07-18）**：不管明槓暗槓，槓本身都不計台
（`OPEN_KONG_TAI` / `CONCEALED_KONG_TAI` = 0）。只有兩種情況會計，各 1 台：胡在槓
補上來的那張牌（槓上開花），還有搶槓。槓上開花要求第四張是自己摸來的（暗槓或加槓）；
大明槓（第四張是別人切出來的）不算。暗槓保住門清、也算進暗刻台；明槓會破門清。所以
在這裡，大明槓其實是虧的：0 台、沒多破什麼、還放棄了槓上開花。
[docs/experiments.md](docs/experiments.md) 的自對局實驗也證實了這件事。至於全求人，
本專案採台灣最常見的解釋：大明槓算一組「靠別人湊成」的面子、可以算全求人，但只要
有暗槓就不算，因為那組不是靠別人的牌完成的。如果你的牌桌規則不一樣，記得改這裡。

**連莊雙向溢價**：莊家的加成（莊 `DEALER_TAI` 1 + 連 N 拉 N 的 `STREAK_TAI_PER_WIN`
× 連莊數）會套在「莊家和胡家之間」的每一筆付款上。莊家自己胡的時候，這個加成直接
算進整副牌的價值（每家都付）；換閒家胡時，`selfplay._dealer_leg_premium` 只把它加
到莊家那一筆——也就是榮和放槍給莊，或莊家在別人自摸時要付的那份。就算連莊 0，莊家
要付的那筆也比一般閒家貴一單位。流局連莊：流局或莊家胡都讓莊續坐、連莊數 +1。

一些疊台的處理方式：小三元／大三元會取代它們本來的三元牌刻；小四喜／大四喜會蓋過
圈風／門風。單獨一組三元刻、或不在四喜裡的風牌，還是照常計。字一色可以和碰碰胡、
暗刻台一起疊；暗刻只算最高那一級；平胡要全順、將牌不是字牌、而且是多門聽（自摸
可以）。程式會把所有胡牌拆法都列出來，取台數最高的那種。榮和湊成的刻子不算暗刻；
獨聽就是只有一種牌能胡。

```bash
python3 -m taimahjong "123m111555666777z22z" --score --win-tile 2z
python3 -m taimahjong "22z" --score --my-melds "123m;456p;789s;111z;555z" \
  --win-tile 2z --dealer --streak 2 --migi
```

可以另外加的旗標：`--self-draw --dealer --streak N --migi --heavenly --earthly
--round-wind 1z --seat-wind 2z`。

## M5b 用「台」估算 EV

EV 就是期望值：把一個決定平均下來，大概值多少台。`taimahjong.ev` 會挑一小組
M2 高效切牌，用「台」當單位估它們的 EV。胡牌的價值算成 `BASE_UNITS + M5a 台數`，
這樣賺的和賠的用同一個單位比：

```
attack_ev = P(自摸胡) * E[value_units | 自摸胡]
net_ev    = attack_ev - sum(E[每個對手的放槍損失])
E[loss]  = P(放槍 | 危險) * 對手狀態因子 * 可見狀態價值
```

進攻這側只算自摸。下面 M7 會再加上「撐不撐得到下次摸牌」的折扣，還有流局的項。
放槍的機率是對機器人算出來的平均值，不是真人牌局的模型。對手價值一樣是**還沒校準**
的估計，只看得到的線索：基本盤、migi、亮在外面的三元刻、同花的樣子、還有全刻子的
傾向。查不到校準資料時，就退回用 0.02 乘上 M4a 危險；被 migi 排除的牌一樣是 0。

`--ev` 吃一副 17 張的手牌和一個對手（可不給），一樣可以用 `--opp-river`、
`--opp-melds`、`--opp-declared`、`--visible`。它會顯示切哪張、淨 EV、自摸胡的機率、
胡了大概值幾台、還有損失。預設每個候選跑 400 次模擬（通常十秒內跑完）：

```bash
python3 -m taimahjong "123m123p123s11122233z" --ev --opp-river "1m2m" \
  --opp-declared 0 --turns 3 --sims 400 --seed 7
```

`--declare` 吃一副 16 張的聽牌。它的「宣告」那條路會把現在的聽口鎖死，用機率公式
算出你在 `--turns` 巡內摸到的準確機會；「不宣告」那條路則照正常打法模擬，還有機會
換更大的牌。宣告那條會把 migi 的 8 台算進去。

```bash
python3 -m taimahjong "123m123p123s1112223z" --declare --turns 3 --sims 400 --seed 7
```

## M5c 有算點數的自對局

自對局結束時現在會算平衡的點數。榮和是實際放槍的人付給胡家全部的分；自摸是另外
三家各付全部；流局是 0。新的 `ev_aware` 策略是一種「照公式直接排名」的打法：拿
M2 前五名候選加上危險最低的那張，把「向聽／進張的進攻價值」和「校準後對每家的
放槍損失」放在一起權衡。它每次決定**不**跑蒙地卡羅，所以快。

已提交的 v2 校準是 2,000 局的混合陣容，策略是 `attack,cautious,ev_aware,ev_aware`，
種子接續 30001–30037、用逐對手的危險算法。跑一段一樣設定的資料：

```bash
python3 -m taimahjong --selfplay --games 25 --seed 30038 \
  --policies attack,cautious,ev_aware,ev_aware --out data/calibration.json
```

策略對打時，每種策略派兩個機器人，每局輪流讓其中一種坐莊，種子用固定連號
41000–42199：

| 局數 | ev_aware 每座每局點數 | attack 每座每局點數 | ev_aware − attack | SE |
| ---: | ---: | ---: | ---: | ---: |
| 1,200 | -1.911 | 1.911 | -3.823 | 0.119 |

從這個樣本看，attack 贏（大約差 32 個標準誤，差距很明顯）；看到結果後我們沒有為此
去調任何策略參數。同一組 100 局固定種子的測試裡，ev_aware 跑 88.32 秒、attack 跑
48.96 秒（慢 1.804 倍）。想要可重現的批次摘要，用 `scripts/head_to_head.py
--games N --seed S`。

## M7 存活折扣 EV 與流局

M7 要處理一件事：在你下次摸牌之前，別家可能先胡了。它一樣**還沒校準**，是「每一巡
各自獨立」的粗估，目的是讓「該防守、該蓋牌」看得出來，不是要宣稱它算得準真人牌局。
對每個對手，一巡的風險是這樣算的：

```
BASE_OPPONENT_HAZARD (0.03)
* clamp(tenpai_score / BASELINE_TENPAI_RATE (0.25), 0.25, 3.0)
* 當 fold_score >= FOLD_HAZARD_CUTOFF (0.60) 時為 0，否則為 1
```

宣告 migi 的對手，聽牌分數直接算 1.0。程式把這些風險加起來，用「存活率」
`S(t) = product(1 − 全部風險)` 算你能撐過每一次摸牌的機會，再用 `S(t)` 幫每次
模擬「第一次胡」的收益打折。CLI 會同時給你原始 `P(win)` 和打折後的 `P(win)`。

還有一條專門算流局的路：

```
P(draw) = S(T) * (1 - P(在 T 巡內胡))
net_ev  = 打折後的進攻 EV - 風險 EV + P(draw) * DRAW_VALUE
```

`DRAW_VALUE` 預設是 `0.0`，對應「沒聽牌不用罰」的家規。它留成常數，你要改成別的
值也行。流局後莊家續莊、連莊那些效果，不在這裡處理。

用 `--ev` 和 `--declare` 時，如果你不給 `--turns`，程式會自己從牌桌推你還能摸幾次：
`ceil((136 − 16 牌山尾 − 看得到的牌 − 你的手牌) / 4)`。你自己給 `--turns` 就會蓋過
這個估算。`--ev` 還會在最後多印一列 `fold`。那是建議、不是叫你真的切那張：它把
進攻 EV 當 0、用畫面上切牌裡「當下能拿到的最低放槍 EV」、只留下存活折扣後的流局項。

自動算巡數、又有一個有威脅的對手的例子：

```bash
python3 -m taimahjong "123m123p123s11122233z" --ev --opp-river "123456789m" --sims 400 --seed 7
```

這些風險常數、假設每巡獨立、還有把放槍平均值和這個存活模型湊在一起，通通都是粗估。
它們不是校準過的胡牌機率，別當成那樣用。

## M6 教學測驗

`--quiz` 把自對局變成切牌練習題。它在某家摸牌之後馬上把那個座位拍一張快照，只留
那家看得到的東西：自己的手牌、自家牌河和副露、每個對手的牌河（含摸切／手切）、
鳴出的副露、有沒有宣告、還有看得到的牌的總數。對手的暗牌永遠不會外流。

從你指定的種子開始，程式會先試那一局，再一路往後試，最多試 80 次
（`MAX_ATTEMPTS`）。一個好題目要滿足這些條件：向聽最多 2（`SHANTEN_MAX`）、至少
第 5 巡（`MIN_TURN`）、有一個對手是兩副露、或宣告過、或聽牌估計至少 0.40，而且
最好和最差的切牌之間 EV 至少差 0.8 台（`EV_GAP_MIN`）——差太少就沒鑑別度。表格先
用每候選 24 次模擬排名，再把「排名最好的」和「你選的」那兩張用 200 次重估（同一組
隨機種子，好讓比較公平）。如果結果剛好卡在判定邊界、又接近聽牌，就再用 800 次算
一次。`QuizGrade.refined_sims` 記是哪一輪算出最後結果；`marginal`（介面上寫「邊緣」）
表示最後結果還是很貼邊界。由題目種子衍生的種子，可以完整重現這一題。

你可以直接給答案做自動檢查，也可以不給、互動式回答一題：

```bash
python3 -m taimahjong --quiz --seed 1 --answer 9s
python3 -m taimahjong --quiz --seed 1
python3 -m taimahjong --quiz-batch 5 --seed 1
```

判定分四種：`best`（零損失）、`good`（少於 0.3 台，`GOOD_DELTA`）、`inaccuracy`
（少於 1.0 台）、`mistake`（1.0 台以上）。CLI 的 EV 都印一位小數。解說用的是和
`--ev` 一樣的表，然後告訴你最關鍵的是「胡牌 EV」還是「對手損失」那一項。

## M9 Web 教學介面（W1–W3：FastAPI + SPA）

裝好套件後，在專案根目錄開 API 和網頁：

```bash
pip install -r requirements.txt
uvicorn server.api:app
# 瀏覽 http://127.0.0.1:8000/
```

網頁是單頁應用（`server/static/`，用原生 ES modules，不用建置）。裡面有三種訓練
模式、一個教學區、兩個工具：整場（一局打到底，每個切牌／鳴牌／槓都即時打 EV 分）、
單手（抽一題練切牌）、殘局（牌快摸完的高壓局面，會自動標進攻題還是防守題）、教學、
切牌分析、算台。牌桌畫成雀魂那種十字河（四家牌河往中間聚、手牌在你這端），回饋做成
GTO Wizard 那種樣子（判定徽章、EV 差多少、標出正解、可以展開的 EV 排名表）。每種
模式的作答紀錄存在瀏覽器的 localStorage，首頁會畫每種模式的最佳率走勢。桌面固定寫
「本桌無花牌」。JSON API 看 `server/api.py`（`/api/quiz`、`/api/endgame`、
`/api/trainer`、`/api/ev/rank`、`/api/score`、`/api/ukeire`）。

**底/台方案（`taimahjong.scoring.ScoringScheme`）**：練習牌桌上可以切底3台1 ⇄ 底5台2。
底和台的比例會改變「先求胡」還是「拚大牌」的取捨，所以有時最佳切牌也會跟著變——一
切換就重新打分（同一種子還是同一局面，只有分數吃你選的方案）。底3台1 是家規預設，
等於舊的 `BASE_UNITS`；自對局、校準、CLI 一律用預設，不受影響。老實說：守備側的
對手價值還沒校準，所以換方案後大部分決定都變動不大，主要影響那些很接近的局面。

**教學區（`server/static/js/lessons.js`）**：幾題手寫的基本牌效（孤張進聽、同樣聽
牌選比較寬的、急聽還是留寬型、吃碰要不要保門清），每題都用 `/api/ukeire`（純進張、
確定性、不跑蒙地卡羅）當場驗證。切牌題會顯示每一切的向聽／進張排名並標正解，吃碰題
會把兩種選法的進張並排比。

核心引擎沒有任何 Web 相依，API 層只是直接呼叫本來就有的 Python 介面。舊的 Streamlit
版（`webapp/app.py`）在 SPA 功能追上之後，已於 2026-07-20 退役。

### 實戰訓練器（M10，Phase 1）

「實戰」分頁用 `taimahjong.trainer.play_trainer` 生成器一手一手推進一局：輪到你切牌
就暫停，你選完馬上用 `quiz.grade` 給 EV 判定（最佳／不錯／小失誤／失誤），並累計最佳
率和總 EV 損失，一直打到胡／放槍／流局再給總結。Phase 1 你這家打門清（可以自摸、榮和，
暫時不能吃碰），對手正常鳴牌；你的鳴牌決策和鳴牌 EV 留到 Phase 2。所有機率一樣是對
機器人校準、不是真人牌局。

開新局時可以選座位（莊家／莊的下家／對家／上家）和一開始的連莊數。莊固定坐座位 0，
過莊時引擎改用「輪轉你的座位」來模擬，讓你體會坐在莊的不同相對位置。連莊會拉高莊胡
的價值，也拉高放槍給莊的代價（看上面 M5a 的連莊雙向規則）。「再來一局」會依莊胡／
流局續莊、或閒胡過莊，自動更新連莊數和座位。

這個工具是設計給一個人在自己電腦上用的（對局狀態存在 API 行程的記憶體裡）。

## M11 自對局實驗：連莊防守與槓的 EV

`scripts/streak_defense.py` 和 `scripts/kong_ev.py` 用配對種子的自對局，量化兩個策略
問題：分座位怎麼防連莊的莊家，還有各種槓的邊際 EV（多開這個槓大概多賺／多賠幾台）。
做法、指令和數據看 [docs/experiments.md](docs/experiments.md)。老實說：進攻側的胡牌
價值是對三家對稱地算，沒有特別多加「胡莊會多收的連莊溢價」（會低估非莊家，量級大約
是一次胡的 P/3 以內）；槓用掉的牌山尾，不會從活牌牆補回來。
